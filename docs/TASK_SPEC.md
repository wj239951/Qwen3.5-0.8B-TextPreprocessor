# 任务规范：输入文本清洗规范化（v1.0）

本文件是**数据标注、规则实现、模型评测三方的唯一契约**。任何一条训练样本的"标准答案"
都必须能由本规范逐条推导出来。

## 1. 任务定义

- 输入：一段原始文本 `raw`（可能来自复制粘贴、OCR、聊天软件转发、HTML 抓取、代码块、多语言混排）。
- 输出：清洗后的纯文本 `clean`。
- 形态：单轮、无解释、无 Markdown 包裹，模型直接输出 `clean`。

### 允许做的（白名单）

| # | 操作 | 说明 |
|---|---|---|
| 1 | 删除不可见字符 | 零宽空格/连接符、BOM、软连字符、方向控制符、除 `\n` `\t` 外的控制字符 |
| 2 | 去 HTML | 解码实体（`&amp;` `&nbsp;` `&#39;`）；标签转文本，块级标签转换行 |
| 3 | 宽度归一 | 全角字母/数字 → 半角；全角空格、NBSP、窄空格 → 半角空格 |
| 4 | 标点归一 | 中文语境下半角 `, ; : ! ?` → 全角；`！！！`/`？？？` 压缩；`。。。` → `……` |
| 5 | 重复压缩 | 同一 CJK 字符连续 ≥3 → 1；同一拉丁字母连续 ≥3 → 2；数字永不压缩 |
| 6 | 空白归一 | 行尾空白删除、行首缩进删除、连续空格 → 1、连续空行 → 1 |
| 7 | 硬换行合并 | 段落内因排版被折断的行，合并回一行（见 §4） |
| 8 | 首尾清理 | 去掉整段首尾空白与末尾多余空行 |

> **乱码修复不在这张表里。** 把 `æ˜Žå¤©` 还原成"明天"需要逐字节重排，这是确定性
> 代码的活（见 `repair_mojibake()`），不是 0.8B 模型能稳定学会的技能。实测让模型做
> 这件事，它会记住"看到乱码就输出某段中文"，进而**凭空编造整段内容**。所以：
> 乱码请在调用模型之前用 `repair_mojibake()` 处理掉。
> 规则引擎 `clean()` 默认已包含这一步，供纯代码方案直接使用。

### 禁止做的（黑名单）

| # | 操作 | 原因 |
|---|---|---|
| 1 | 改写措辞、润色、纠错病句 | 属于改写任务，会污染下游语义 |
| 2 | 翻译、繁简转换 | 改变字符集，不可逆 |
| 3 | 摘要、扩写、补全 | 会引入原文没有的实词 |
| 4 | 脱敏（手机号/邮箱/身份证打码） | 属于 PII 策略，本模型不负责 |
| 5 | 增删 emoji、话题标签、@提及 | 它们是内容不是噪声 |
| 6 | 调整段落顺序、合并不同段落 | 只处理"同一段落内部的排版折断" |
| 7 | 输出解释、前后缀、代码围栏 | 输出必须能直接回填 |

## 2. 关键判定

### 2.1 中英文之间的空格

**不主动插入**。原文 `hello世界` 保持 `hello世界`，只有原文已有空格时才做压缩。
理由：插入空格属于排版偏好，不同下游系统要求不同，且会改动用户原文。

### 2.2 全角标点的边界

`，。！？：；（）` 是中文标点，**保留全角**。只有当半角标点夹在**两个 CJK 字符之间**时才转全角：

- `你好,世界` → `你好，世界`
- `版本 1.2.3 发布` → 不变（数字语境）
- `README.md` → 不变（拉丁语境）

### 2.3 重复字符压缩的例外

- 数字：`1000000` 保持不变（不得压缩）。
- 两字叠词：**保留**。`谢谢`、`刚刚`、`妈妈`、`看看` 都是合法词，规则的阈值定在 3 次，
  就是为了不误伤它们。
- 语气拖长：`哈哈哈哈哈` → `哈`（≥3 次按规则压到 1 次）。
- 英文：`sooooo good` → `soo good`（≥3 次压到 2 次，保留口语感）。
- 已知代价：`谢谢谢谢` 会被压成 `谢`。这条规则牺牲了极端情况下的自然度，
  换来的是"绝不误伤两字词"的稳定性。

### 2.4 URL / 邮箱 / 代码

保持原样，不做任何宽度或标点转换。检测到 `http(s)://`、`www.`、`@`、反引号围栏内的内容时跳过第 4、5 条。

### 2.5 空输入

空字符串、纯空白、纯不可见字符 → 输出空字符串。

## 3. 处理顺序

顺序不可交换，规则实现与标注必须一致：

```
0  乱码修复（字节层，调用模型前先做：repair_mojibake）
1  统一换行 CRLF/CR → LF
2  删除不可见/控制字符（含残留 C1）
3  HTML 解码 + 标签处理
4  宽度归一（保护 URL/邮箱/代码）
5  标点归一（保护 URL/邮箱/代码）
6  重复字符压缩
7  行级清理（行首行尾空白）
8  硬换行合并
9  空白归一（空格、空行）
10 首尾清理
```

> 第 0 步必须在所有步骤之前：乱码的原始字节里包含 C1 控制符（U+0080–U+009F）和
> U+00AD 软连字符，先按"不可见字符"删掉，就再也拼不回原始 UTF-8 字节序列了。

## 4. 硬换行合并的判定条件

同时满足 4 条才合并当前行与下一行：

1. 当前行不以终止标点结尾：`。 ！ ？ ! ? ： : ； ; ， , 、 … ） ) ” " '` ；
2. 下一行不是列表/标题/引用项：不以 `- * + • 1. # > |` 开头；
3. 当前行长度 ≥ 24 个字符（短行更可能是有意换行）；
4. 下一行不是空行、且不是纯符号行。

合并时的连接符：两侧都是 CJK 或一侧为 CJK 标点 → 不加空格；两侧都是拉丁/数字 → 加一个空格。

## 5. 输出格式

- 仅一段纯文本，允许内部有单空行分段。
- 无前后缀、无 ` ``` `、无"清洗结果："之类引导语。
- 末尾不保留换行。

## 6. 已知边界（不做承诺）

- 无法修复的乱码（`锟斤拷` 之外的 GBK/UTF-8 二次损坏）保持原样。
- HTML 中 `a < b` 这类数学比较不会被误删（需 ≥2 个成对标签才判定为 HTML）。
- 表格的列对齐依赖空格，本版本会压缩为单空格（表格结构不保证保留）。
